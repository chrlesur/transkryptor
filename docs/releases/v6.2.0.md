# Release Notes — Transkryptor v6.2.0

Date de préparation : 2026-07-06
Branche cible : `main`

## Résumé

Transkryptor v6.2.0 corrige l'incident production où les endpoints
`/api/analyze`, `/api/synthesize` et `/api/diarize` échouaient avec les modèles
Mistral, notamment `mistral-small4:119b`, car le backend envoyait toujours
`enable_thinking: false` à Cloud Temple LLMaaS.

Ce paramètre reste nécessaire pour les modèles Qwen reasoning afin de forcer la
réponse dans `message.content`, mais il est rejeté par les tokenizers Mistral
avec HTTP 400.

## Changements

- `enable_thinking: false` est désormais ajouté uniquement pour les modèles
  explicitement identifiés comme thinking (`qwen*`).
- Les payloads Cloud Temple chat completions sont construits par un helper
  commun pour l'analyse, la synthèse et la diarization streaming.
- Les détails d'erreur Axios sont sérialisés avec un fallback sûr afin d'éviter
  le crash `Converting circular structure to JSON`.
- Les logs applicatifs incluent le corps de réponse Cloud Temple lorsqu'il est
  disponible, ce qui rend les diagnostics HTTP 400 exploitables.
- Les versions projet, fallbacks client et fallback serveur sont alignés sur
  `6.2.0`.
- Les URLs d'installation README pointent vers le tag `v6.2.0`.

## Impact utilisateur

- Les utilisateurs qui sélectionnent `mistral-small4:119b` peuvent à nouveau
  exécuter l'analyse, la synthèse et la diarization.
- Les modèles Qwen reasoning continuent de recevoir `enable_thinking: false`,
  pour éviter que la sortie utile arrive uniquement dans `message.reasoning`.
- Aucun changement d'infrastructure ni nouvelle variable d'environnement.

## Commande d'installation cible

```bash
curl -fsSL https://raw.githubusercontent.com/Lesur-ai/transkryptor/v6.2.0/scripts/install.sh | bash
```

## Validation recommandée

- Build Docker de l'image applicative.
- Dans le conteneur Docker : `node --check src/server/server.js`.
- Dans le conteneur Docker : `node scripts/check-enable-thinking-fix.js`.
- Smoke test HTTP Docker `GET /api/version` attendu : `6.2.0`.
- En environnement RUN avec clé Cloud Temple : appels `/api/analyze`,
  `/api/synthesize` et `/api/diarize` avec `mistral-small4:119b` et un modèle
  Qwen autorisé.
